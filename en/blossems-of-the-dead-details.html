Before You Cross

Introduction

Before You Cross is a game created for my final year project in my Goldsmiths University Game Design course. The game is a 3D puzzle based platformer being developed in Unreal Engine. I am working with 3 other team members to create this game.

The character navigates through the land of the dead, switching between soul forms to solve puzzles, and ultimately find her deceased grandmother, wishing her one final goodbye. Dimension-switching serves as the core gameplay loop, requiring the player to alternate between different soul forms to solve environmental puzzles and explore the world.

I am responsible for:

  • Programming the game's core mechanics and systems
  • Mechanic Design involving soul switching
  • UI/UX Design for the game's interface

Scripting

My Responsibility

As the main Technical Designer and programmer of this project, I am not only responsible for implementing most of the mechanics in the game, but also ensuring the program is well-structured, maintainable, reusable, and that the mechanics can be implemented with reasonable effort.

As a dimension-switching puzzle-platformer, the game teleports the player between two parallel worlds stacked along the Y-axis. Both worlds share common sub-levels, allowing shared assets and interactive items to be updated universally in a single scene. Checkpoint systems, fire interactables, enemy behaviours and other objects that have different properties in each world are incorporated into this dimension-switching system.

Particle effects for wind and flame are implemented using material shaders and the Niagara Particle System, which produces particles efficiently with a multitude of parameter settings to ensure best visual quality.

I am also mainly responsible for implementing the Bagua matching puzzle system within the second level of the game, which obtained paintings are matched with trigrams within the Bagua. I used a data-driven approach where a single modular script handles all trigrams, using each object's sprite reference as a unique ID to validate correct placement.

Mechanic Design

My Responsibility

I was tasked upon thinking about interesting mechanic designs to give more variety to the game. preventing it from becoming just a walking simulator. Although not all ideas are chosen and implemented in the end, each idea is thought out through creating diagrams.

My ideas

State switching is decided as the main mechanic of the game, so I suggested a multitude of sub-mechanics which revolve around the state switching idea. Since the state switching mechanic is based on Sol Flames, I thought about how flames can be extinguished by wind and how it can light up objects, which I expanded upon these ideas. The diagrams below only show part of the ideas I have planned and discussed with my team.

I have also designed the Bagua matching puzzle system residing at the ground floor of a tower within the second level. Since the game has other puzzles with a relatively long runtime for a university project, I decided to design a simple puzzle that is both easy to understand and simple to play. The player is required to find paintings within the tower and place these paintings into the correct trigram within the Bagua, with hints provided by a billboard showing matching patterns.

UI/UX Design

My Responsibility

I designed and implemented the game's entire UI and UX systems, covering both head-up overlays and world-space interactable objects. These UI and UX elements are designed to be simple yet achieves the goal of providing the player with information and improve navigability within the game.

My Ideas

Similarly to how I usually plan UI designs, I start off with a wireframe diagram with notes, then only execute the design into the final interface when agreed upon by the team. Since the player will obtain 3 sol flames within the game, the progression of the flames is shown in the overlay UI. I initially designed an overlay with a cooldown bar for the 3 collectable Sol Flames, but simplified this later when the cooldown mechanic was cut.

In-Game UI Wireframe State 1 [Scrapped]
In-Game UI Wireframe State 2 [Scrapped]

The game provides the player with text throughout the game in the form of dialogue boxes and cutscenes, both to enrich the narrative and to improve world-building. Initially, only a interactable dialogue box is designed appearing when the player physically interacts with a character. It was later proven that the player doesn't have time to interact with every NPC in the area individually, so I referenced other games like Paper Mario and designed floating dialogue boxes above the NPCs, which are triggered when the player is within a certain distance of the NPC.

The game has intro and ending cutscenes, and have to be implemented in a way that is easy to edit and maintain while being simplistic due to the game's limited development time. I chosen to use static images to display certain events accompanied by text at the bottom of the image.

Final Implementation

Object Interaction is a major part of the game, and the player requires indication on what is interactable and what isn't. Initially, interactable objects within the player's reach is shown using a yellow outline around its mesh, but was later changed to mesh highlighting using a blue texture when the former was proven to be not visually significant enough for some players to notice. For the Bagua matching puzzle, colour changes are not only used to indicate interactable trigrams, but also to indicate the correct placement of paintings within the Bagua.
